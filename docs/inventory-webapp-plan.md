# Inventory Review Webapp — Implementation Plan

**Linear:** [GR-6](https://linear.app/dentaway/issue/GR-6/webapp-for-inventory-review-and-summary-from-sqlite-excel-take-off)

**Goal:** A webapp that lets an estimator select a project, review per-drawing inventory (approve / exclude / amend), view source PDFs (with overlays when available), and see summaries by floor or by category. No rates, labour or costs in this slice.

This is likely to become the app users log into.

## Tech stack

Inspired by the observability stack in [DentAway/dental-jobs](https://github.com/DentAway/dental-jobs) (`jobs/observability/`):

| Layer | Choice | Why |
|---|---|---|
| Backend API | **FastAPI** (Python 3.12+) | Reuses `riser_extract`, matches monorepo style, OpenAPI out of the box |
| Frontend | **React** (Vite) + Tremor / shadcn-style components | Same pattern as the observability UI; strong tables, filters, summaries |
| Database | **SQLite** (local/MVP) → **Postgres** (multi-user) | SQLite for single-user review; Postgres when auth + concurrent estimators land |
| Auth | Google Workspace (later) | Already noted in `docs/riser/technical-execution.md` |
| PDF / overlays | API-served files + PDF.js or react-pdf | Overlay PDFs generated by `riser_extract` can be layered or side-by-side |
| Packaging | Independent package under `apps/inventory_webapp/` with its own `pyproject.toml` + `uv.lock` | Matches dental-jobs monorepo pattern |

Streamlit is only a short-lived prototype (not in this plan). The logged-in product is FastAPI + React.

## Domain objects (aligned with technical-execution.md)

- **Project** — name, code, notes
- **Document / Drawing** — floor_tab_name, drawing_number, title, scale, source_pdf, overlay_pdf
- **Occurrence / Inventory item** — line, category, annotation, linked_to, count, unit, size, tender_estimate, measurement_type (`printed` / `scaled` / `geometry` / `vertical` / `specified-not-drawn` / `excluded`), scope (`in` / `interface` / `out`), notes, status (`pending` / `approved` / `excluded` / `amended`), amended_count, amended_notes, reviewed_at

Floor is a property of the drawing, not part of the item ID. Amber / inferred rows are those whose `measurement_type` is not `printed`.

## Implementation slices

### Slice 0 — Package skeleton & seed

**Done when:** `uv run` starts a FastAPI app that serves seeded Hubby data from SQLite.

- Create `apps/inventory_webapp/` with:
  - `pyproject.toml` (fastapi, uvicorn, pydantic, sqlite3 via stdlib or SQLAlchemy, openpyxl)
  - `app/main.py` — FastAPI app, CORS for local Vite
  - `app/db.py` — SQLite connection + init
  - `app/models.py` — Pydantic models matching the domain objects above
  - `app/seed.py` — loads Hubby Excel or falls back to `evals/datasets/hubby-premier-inn-london/expected/floors.json`
- Seed creates one project (“Hub by Premier Inn Putney”), one drawing per floor/tab (Basement → Roof Plant, First Floor marked interpolated), and inventory rows from the Excel headlines + detail lines.
- Endpoint: `GET /health`, `GET /projects`.

### Slice 1 — Core API

**Done when:** All review and summary endpoints work against the seeded DB.

| Method | Path | Purpose |
|---|---|---|
| GET | `/projects` | List projects |
| GET | `/projects/{id}/drawings` | Drawings for a project |
| GET | `/drawings/{id}/items` | Inventory items (filterable by status, measurement_type, scope) |
| PATCH | `/items/{id}` | Update status, amended_count, amended_notes |
| POST | `/drawings/{id}/items/bulk` | Bulk approve / exclude pending |
| GET | `/projects/{id}/summary/by-floor` | Approved qty grouped by floor |
| GET | `/projects/{id}/summary/by-category` | Approved qty grouped by category |
| GET | `/drawings/{id}/pdf` | Stream source PDF (when path known) |
| GET | `/drawings/{id}/overlay` | Stream overlay PDF |

- All write endpoints stamp `reviewed_at`.
- Summary queries use `COALESCE(amended_count, tender_estimate, count)` for approved rows only.
- OpenAPI docs at `/docs`.

### Slice 2 — React UI (project + drawing review)

**Done when:** Estimator can pick a project, open a drawing, approve/exclude/amend items, and see changes persist.

- Vite + React app under `apps/inventory_webapp/ui/`.
- Pages:
  - `/` — project picker (cards or select)
  - `/projects/:id` — drawing list (sidebar or table) + summary tabs
  - `/projects/:id/drawings/:drawingId` — inventory table
- Inventory table:
  - Columns: line, annotation, count, unit, size, tender, measurement_type, scope, status, amended count, notes
  - Inline edit or modal for amend
  - Row actions: Approve / Exclude
  - Bulk actions: Approve all pending / Exclude all pending
  - Amber highlight when `measurement_type != printed`
- Use Tremor or a light table component (same style as observability UI).
- Optimistic updates + refetch on save.

### Slice 3 — Summaries

**Done when:** Summary views match the Excel Summary tab shape (by floor and by category).

- Tabs on the project page:
  - By floor — one row per drawing, approved qty, excluded count
  - By category — one row per category, approved qty
- Optional filters: only approved, hide zero, measurement_type.
- Export current view as CSV (client-side) for quick Excel round-trip.

### Slice 4 — PDF viewer + overlays

**Done when:** Opening a drawing shows the source PDF; overlay PDF (when present) is visible.

- PDF.js or react-pdf viewer in a split pane or tab.
- If `overlay_pdf` exists, offer “Show annotations” toggle that layers or swaps the overlay.
- Fallback: link to open PDF in a new tab when the file is missing or too large.
- Later: map occurrence `pixel_bbox` to clickable highlights on the raster (not required for this slice).

### Slice 5 — Auth & multi-user (later)

**Done when:** Google Workspace sign-in works and review decisions are per-user.

- Google OAuth (or Clerk) on the FastAPI side.
- Replace SQLite with Postgres.
- Add `reviewed_by` column.
- Project-level permissions (later).

## Seeding details

- Prefer the Hubby Excel (`25280-SEN Heating and Cooling Inventory - All Floors - last.xlsx`).
- Parse each floor tab: skip Summary, treat First Floor as interpolated (flag in notes).
- Map Excel columns roughly to: line (A), annotation (B), linked_to (C), count (D), unit (E), size (F), tender (G), notes (I).
- Set `measurement_type` from notes keywords (`ESTIMATE`, `inferred`, `amber`, `not drawn`).
- Fallback: `evals/datasets/hubby-premier-inn-london/expected/floors.json` headlines only.

## Acceptance criteria (GR-6)

- User can select a project and see all drawings.
- User can open a drawing and see its inventory table with approve / exclude / amend.
- Summary can be grouped by floor and by category.
- PDF viewer (or link) available; overlays shown if present.
- Data persists.
- No labour or cost fields.

## Out of scope

- Rates, labour, pricing, Material Rates tab.
- Drive sync / Gmail issue pack.
- Full Excel round-trip with live formulas (later slice).
- Clickable bbox overlays on the raster (later).
- Multi-user permissions beyond basic auth.

## How to run (once implemented)

```bash
cd apps/inventory_webapp
uv sync
uv run python -m app.seed          # creates inventory.db
uv run uvicorn app.main:app --reload --port 8870

cd ui
npm install
npm run dev                        # → http://127.0.0.1:5173
```
